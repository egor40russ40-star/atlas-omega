# ATLAS Mobile 2 — Этап 6. Русификация и навигация

Статус: **ЗАФИКСИРОВАНО**

## 1. Язык приложения

Русский — основной и обязательный язык ATLAS Mobile 2.

Правило архитектуры:

- все пользовательские строки находятся в Android resources;
- Compose не содержит хардкод пользовательских подписей;
- основной `values/strings.xml` — русский;
- дополнительный английский может появиться в `values-en`, но не является обязательным для первой новой версии;
- shell output, имена файлов, команды и исходные технические сообщения не переводятся автоматически.

## 2. Терминологический словарь

Единые названия:

```text
Terminal       → Терминал
Connections    → Подключения
Machines       → Машины
Files          → Файлы
Code           → Код
Jobs           → Задания
Settings       → Настройки
Connected      → Подключено
Connecting     → Подключение
Reconnecting   → Переподключение
Disconnected   → Отключено
Trusted        → Доверенное
Pending trust  → Ожидает подтверждения
Read only      → Только чтение
Save           → Сохранить
Retry          → Повторить
Technical details → Технические детали
```

Технические маркировки вроде `SSH`, `PTY`, `tmux`, `Git`, `API`, `SHA-256` не переводятся.

## 3. Главная навигация

Основные рабочие разделы:

```text
Терминал
Код
Файлы
ATLAS
```

Дополнительные разделы доступны через меню/контекст:

```text
Машины
Подключения
Задания
Мониторинг
Настройки
О приложении
```

На телефоне bottom navigation не должна содержать более четырёх основных рабочих разделов.

## 4. Terminal-first start

Если onboarding завершён и есть доверенный профиль:

```text
App launch → последняя terminal workspace
```

Если профиль отсутствует:

```text
App launch → onboarding/подключение
```

Если профиль есть, но Tailscale/машина недоступны:

```text
App launch → terminal buffer + понятный offline state
```

а не большая форма подключения.

## 5. Status model в UI

Пользователь должен понимать отдельно:

- сеть;
- Gateway;
- machine;
- SSH;
- terminal/tmux.

Пример компактного статуса:

```text
NucBox ● Терминал готов
```

или:

```text
NucBox ◐ Переподключение
```

Расширенная карточка по tap:

```text
Tailscale: доступно
Gateway: доступен
NucBox: доступен
SSH: подключено
PTY: готов
Tmux: прикреплено
```

Не использовать один зелёный `ONLINE` для всех уровней.

## 6. Ошибки

Каждая ошибка содержит два слоя.

### Пользовательский слой

Короткое русское сообщение и действие:

```text
Не удалось подключиться к NucBox.
Проверьте Tailscale и повторите попытку.

[Повторить]
```

### Технический слой

Раскрывается по кнопке:

```text
Технические детали
```

и показывает sanitized exception/original SSH error.

## 7. Онбординг

Первый запуск — короткий мастер:

1. `Добро пожаловать в ATLAS Mobile 2`.
2. Проверка Tailscale/network.
3. Регистрация устройства.
4. Ожидание явного trust.
5. Получение/выбор machine profile.
6. Проверка host key.
7. Пробное подключение.
8. Готово — открыть терминал.

Пользователь не должен вручную заполнять hostname/user/port в обычном managed-пути.

Advanced ручная настройка остаётся доступной отдельно.

## 9. Настройка панели клавиш

Экран-конструктор:

- drag-and-drop клавиш;
- две строки;
- несколько presets;
- `Сбросить по умолчанию`;
- preview;
- отдельный landscape preset.

Базовый preset называется `Программирование`.

## 10. Accessibility

- touch targets не меньше рекомендуемых Android размеров;
- крупные критические кнопки;
- контрастный terminal toolbar;
- состояние не кодируется только цветом;
- поддержка системного масштаба шрифта для UI;
- terminal font scale хранится отдельно, чтобы системное увеличение не разрушало количество колонок неожиданно;
- TalkBack labels для иконок и navigation actions.

## 11. Ориентация

Portrait — основной mobile workflow.

Landscape:

- terminal использует максимум площади;
- bottom navigation может стать compact rail;
- keyboard row остаётся доступным;
- code/terminal split допускается при достаточной ширине.

## 12. Подтверждения

Подтверждение требуется для:

- доверия новому host key;
- замены изменившегося host key;
- revoke устройства;
- удаления удалённого файла;
- закрытия non-persistent terminal session с работающим процессом, если это можно определить;
- destructive ATLAS actions, если такие когда-либо появятся.

Не запрашивать подтверждение для обычных navigation действий.

## 13. Никакой искусственной русификации shell

Приложение не заменяет:

```text
Permission denied
Traceback
fatal: ...
systemctl
pip
pytest
```

на русский внутри терминала.

Вместо этого UI может добавить русскую диагностическую подсказку отдельно от исходного вывода.

## 14. Экран ATLAS

`ATLAS` — не WebView-first контейнер. Долгосрочно это native Compose UI для основных функций Control Plane.

На этапе совместимости допускается isolated legacy/web view для функций, которых ещё нет в native client, но он не должен владеть общей навигацией и не используется для terminal.

## 15. Основной UX-критерий

Пользователь после открытия приложения должен попасть от иконки до ввода команды в уже настроенной системе максимум за одно действие или автоматически.

Нормальный ежедневный путь:

```text
Открыть приложение → терминал готов → писать код
```

а не:

```text
Открыть → ввести host → выбрать key → ввести параметры → connect
```
